# Сервис загрузки в Дзен

## Размещение на Galvanize, 4 октября 2026

Подготовлено размещение отдельной очереди по `https://galvanize.ru/dz/`: nginx снимает prefix /dz, FastAPI получает root_path=/dz, интерфейс обращается к /dz/api/v1. Python-клиент теперь принимает HTTPS URL сервиса с prefix; удалённый HTTP без TLS отклоняется.

Релиз сервера: `/srv/projects/dzen-autopost/releases/20261004-dz-v1`; служба `dzen-autopost.service`; upstream только `127.0.0.1:8766`; runtime `/var/lib/dzen-autopost`, ключ `api-token.txt` (режим 0600), отдельный системный пользователь. Порт 8765 на сервере занят другим сервисом и не используется. Факт запуска подтверждается отдельным deployment receipt и health, а не наличием этих путей в инструкции.

Для сервера обновлены зависимости после аудита: версии зафиксированы в requirements-dzen.txt. Полный проверенный freeze и аудит находятся в verified-requirements.txt / audit.json каталога релиза. Проверки prefix, Host и безопасного HTTPS-клиента добавлены к исходным тестам: всего 17. Локальный Windows-интерпретатор может оставаться со старыми библиотеками; сервер проверяется своим изолированным venv.

Транспорт Дзена остаётся отключён. Этот deployment предоставляет очередь/API/панель; вход в Дзен и публикация отсутствуют. Материалы принимаются только по ключу сервиса, с ограничением частоты и размера запросов в nginx. Ключ не хранится в исходниках, журнале или документации. Ищущие роботы получают noindex.

Источники по prefix: [FastAPI behind a proxy](https://fastapi.tiangolo.com/advanced/behind-a-proxy/). При плановом rollback восстанавливается `/srv/backups/dzen-autopost-20261004-dz-v1/galvanize.ru.conf.before`, удаляются только добавленные snippets/limits данного сервиса, nginx -t → reload, затем новая служба останавливается. Данные /var/lib/dzen-autopost сохраняются. Если конфиг nginx был изменён после deployment другим владельцем, сначала сравнить diff и убрать только /dz include вместо слепой полной замены.

Проверено 3 октября 2026: 15 локальных тестов проходят. Запущенный HTTP-сервис принял через API оригинальную пробную статью СДЭК с 25 блоками и тремя изображениями. Worker переводит её в BLOCKED с DZEN_TRANSPORT_UNAVAILABLE, ссылок на публикацию или черновик в Дзен нет. Реальных запросов в Дзен при этих проверках не было.

Переносимый архив собирается командой `python scripts/package_dzen_service.py`. Он содержит исходники, конфигурацию пяти каналов, клиент, тесты, инструкцию и оригинальный пример статьи. Токен, база очереди и пользовательские runtime-файлы в него не включаются. На другом компьютере нужно распаковать архив, установить зависимости и запустить сервис; локальный ключ создастся заново. Это пакет версии с отключённым транспортом, не готовый автопубликатор.

## Запуск и передача другому проекту

Локальный интерфейс: `http://127.0.0.1:8765`. Запуск из корня проекта:

```powershell
python -m pip install -r requirements-dzen.txt
python scripts/run_dzen_autopost.py --port 8765
```

На этом компьютере зависимости уже доступны. Сервис слушает только loopback. Один процесс, один worker. Для остановки используйте Ctrl+C в терминале запуска. При фоновом запуске PID записан в `%LOCALAPPDATA%\DzenAutopostService\service-info.json`.

Ключ API: `%LOCALAPPDATA%\DzenAutopostService\api-token.txt`. Вставьте его в локальном интерфейсе; не отправляйте ключ в чат. Все статьи, изображения и очередь хранятся в этом же runtime-каталоге. Не включайте runtime-каталог в Git или переносимый пакет. Авторизации в Дзен у этой версии нет.

Другому проекту можно передать пакет исходников и использовать Python-клиент:

```python
from pathlib import Path
from product_kb.dzen_autopost_client import DzenQueueClient

# Значение ключа берётся из локального файла или хранилища секретов проекта.
client = DzenQueueClient(token)
image = client.upload_image(Path("illustration.png"))
job = client.submit({
    "project_key": "krutizmi",
    "title": "Заголовок статьи",
    "blocks": [
        {"type": "paragraph", "text": "Текст статьи."},
        {"type": "image", "media_id": image, "caption": "Подпись"},
    ],
    "mode": "draft",
}, idempotency_key="krutizmi-article-unique-id-v1")
status = client.job(job["id"])
```

Ключ idempotency должен сохраняться в вызывающем проекте вместе со статьёй и повторно использоваться после сбоя связи. Новый ключ означает новое задание. Ключи каналов: galvanize, ernest, lifeplay, krutizmi, cdekarbat. ID сервер получает из `config/dzen-channels.json`; ID существующих пользовательских черновиков не используются.

Демо с тремя оригинальными схемами: `python scripts/demo_dzen_queue.py`. Это исключительно локальная проверка API и сохранения, она не загружает статью в Дзен.

Перед включением автопубликации обязательны разрешённое подключение транспорта, проверка принадлежности канала, загрузка статьи с изображениями, повторное открытие для проверки сохранения, затем проверка второго канала и защита от повторной публикации после сетевого сбоя. Сейчас этих проверок нет, транспорт отключён.

## Цель и границы

Один аккаунт и пять каналов обслуживаются общей очередью. Другой проект передаёт статью, изображения и project_key. ID канала определяется сервером из конфигурации, а не из произвольного запроса клиента.

Это локальная подготовительная версия. Браузерный инструмент запретил доступ к Дзену. Сервис не обходит этот запрет: текущий транспорт всегда возвращает BLOCKED, не делает запросов в Дзен и не принимает cookies. Приём задания, создание локального превью и постановка в очередь не означают публикацию.

Живой транспорт и подтверждение сохранённого контента после повторного открытия остаются обязательными незавершёнными частями. Доработка Dzen Factory сохранена отдельно и в текущем сервере не запускается.

## Контракт

- `GET /health` — состояние и доступность транспорта.
- `GET /api/v1/channels` — пять каналов из серверной конфигурации.
- `POST /api/v1/media` — PNG/JPEG/WebP в base64; возвращает media_id. Файлы проверяются и перекодируются в PNG.
- `POST /api/v1/jobs` — статья с ordered blocks, cover_media_id, режимом draft/publish и необязательным publish_at.
- `GET /api/v1/jobs` и `GET /api/v1/jobs/{id}` — состояние задания.
- `POST /api/v1/jobs/{id}/retry` — повтор заблокированного задания, без создания нового.
- `GET /api/v1/jobs/{id}/preview` — локальное превью.
- `GET /api/v1/media/{id}` — изображение по ID.

API защищён Bearer-токеном. Токен хранится только в runtime-каталоге пользователя, вне проекта. Никаких cookies или паролей Дзена в этом пакете нет. Авторизованный клиент имеет доступ ко всем пяти каналам; это личный сервис одного владельца, не публичный SaaS с разделением прав клиентов.

Пример задания:

```json
{
  "project_key": "galvanize",
  "title": "Заголовок статьи",
  "blocks": [
    {"type": "paragraph", "text": "Первый абзац."},
    {"type": "heading", "text": "Подзаголовок"},
    {"type": "image", "media_id": "<ID загруженного изображения>", "caption": "Подпись"}
  ],
  "mode": "draft"
}
```

POST /jobs требует заголовок `Idempotency-Key`. Повтор того же ключа и содержимого возвращает то же задание. Другие данные с тем же ключом — ошибка 409. Это предотвращает дубли в локальной очереди; гарантия отсутствия дублей на площадке потребует отдельного протокола восстановления живого транспорта.

Статусы: QUEUED → PREPARING → BLOCKED. После разрешённого подключения транспорта возможны VERIFIED_DRAFT / PUBLISHED / UNCERTAIN. Сейчас транспорт выключен, эти состояния не используются. Задание с будущим publish_at остаётся QUEUED до своего времени. Входная дата обязана содержать часовой пояс, в базе хранится UTC; панель отображает местное время браузера.

## Структура и стек

Общий механизм: `product_kb/dzen_autopost.py`. Отдельный FastAPI-сервис: `product_kb_api/dzen_autopost_service.py`. SQLite и runtime-медиа хранятся в `%LOCALAPPDATA%/DzenAutopostService` на Windows. Конфигурация каналов — `config/dzen-channels.json`.

Используются уже установленные FastAPI, Pydantic, Uvicorn и Pillow. Существующий production API, сайты и серверы не изменяются. Из внешнего кода загрузчиков сервис ничего не импортирует.

## План и критерии

1. Сохранение и проверка контента, серверная привязка каналов, идемпотентность, перезапуск и очередь — локальные тесты.
2. API и панель, ограничения размера, авторизация, preview, обработка ошибок — TestClient и реальный localhost.
3. Разрешённый живой транспорт: один черновик с тремя изображениями, read-back и второй канал одного аккаунта. До этого автозагрузка в Дзен не объявляется рабочей.

## Команды

```powershell
python -m pytest tests/test_dzen_autopost.py -q
python scripts/run_dzen_autopost.py --port 8765
```

Запуск только на 127.0.0.1, один процесс/worker. Перезапуск восстанавливает незавершённое локальное PREPARING в QUEUED, поскольку транспорт не выполняет внешних операций. База защищена транзакционным захватом задания. Автозапуск при входе в Windows пока не настроен.

Стиль: обычные Python-функции, явные исключения `ServiceError(code, message, status)`, одинаковые JSON-ошибки `{ "error": { "code": "...", "message": "..." } }`. Нет tenant-specific реализаций.

Верифицированные источники при реализации: [FastAPI lifespan](https://fastapi.tiangolo.com/advanced/events/), [SQLite Python](https://docs.python.org/3/library/sqlite3.html).
